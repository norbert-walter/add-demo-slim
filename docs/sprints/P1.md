## Aufgabe P1.4 – logDump unter der Sperre (Contract V1.5.15)

Review von P1.1–P1.3: `nvs_config` und `system` im Differenztest identisch mit der Referenz,
`log_buffer` einzeln ebenfalls. ThreadSanitizer meldete aber einen Wettlauf: `logDump` kopiert
unter der Sperre nur Indizes und Längen und liest den Text danach ohne Sperre. Neuer Test, der
das ohne Sanitizer zuverlässig findet. Prompt mit Diagnose, ohne Code-Zeilen.

```
Sprint P1, task 4. Branch: work-p1. One new frozen test fails:
test_v1515_dump_never_mixes_lines (test_log_buffer).

Rules: change ONLY logDump in src/comm/log_buffer.cpp. Allowed reads: logDump, the comment in
src/comm/log_buffer.h and the test function named above (grep -n "void <name>" and read only
that function plus the two small helpers lenLine and consistent above it).
Do not modify tests, shims or headers. Do not commit. Report results only by copying tool lines.

Diagnosis (already done): inside the critical section logDump copies only indices and lengths
(LineInfo). After taskEXIT_CRITICAL it reads the line TEXT from the ring - while logLine in another
task may overwrite exactly that slot. The dump then contains mixed lines or a wrong length.
The header (V1.5.15) says: copy the ring TEXT (all lines) inside the critical section into a
file-static copy and work only on that copy afterwards.

Run: pio test -e native -f native/test_log_buffer, then pio test -e native (all green),
then pio run -e firmware-partial -s (must now finish with SUCCESS).
Done when: test_log_buffer 12/12, frozen check clean.
```
