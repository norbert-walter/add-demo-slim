**Was neu ist:** I1 setzt alles zusammen. Damit auch das vorher nativ geprüft werden kann:
- `src/app/net_task.h` (neu) legt den Netzwerk-Task fest: WLAN, HTTP, Speichern der Parameter,
  verzögerter Neustart. `main.cpp` hat eine feste Startreihenfolge. Der Test ersetzt alle
  aufgerufenen Funktionen durch aufzeichnende Platzhalter und prüft die Reihenfolge.
- Für das Display gibt es eine **Nachbildung von LovyanGFX** mit Bildschirmmodell: Sie merkt sich
  die Farbe jedes Pixels und alle sichtbaren Texte mit ihrer Position, und der Test kann den Touch
  setzen. Die Tests prüfen, was auf dem Schirm steht, welche Befehle eine Berührung auslöst
  (immer `source = LOCAL`), dass versteckte Tasten nie senden, ACK erst nach 1 s Halten und nur
  einmal, und dass ein unveränderter Schnappschuss **keinen** Zeichenaufruf erzeugt (kein Flackern).
- `display.h` (V1.5.20) beschreibt das Bild Pixel für Pixel: Bereiche, Texte, Farben, Schriftgrößen.

Den **Gesamt-Build** (`pio run -e firmware`) hat Claude mit der eigenen Referenz bereits gebaut:
RAM 20,7 %, Flash 1,23 MB von 2,9 MB, `check_iram` 5/5.

**Mutationstest vor dem Sprint:** 50 Mutanten der Referenz, im ersten Lauf überlebten 5
(STOP ab x = 384, Berührung außerhalb der ACK-Fläche, Farbe RUNNING, Farbe SHUTTER unabhängig
von HV, und ein gleichwertiger). Dafür gibt es jetzt Prüfungen; übrig bleibt der gleichwertige.

## Erster Flash der vollständigen Firmware (Norbert, auf dem Dell, nach dem Review)

Die Firmware startet die Steuerung: Der Motor bewegt sich **nur auf Befehl** (Taste oder API).
Trotzdem: Schlitten frei, Hand am Not-Aus, Motorversorgung an.

```bash
pio run -e firmware -t upload
```
```bash
pio device monitor
```

**Prüfliste** (Ergebnis je Punkt: ok / Befund):
1. Serieller Monitor: Boot-Banner mit FW 1.0.0, danach `boot: ready` im Log; kein Neustart.
2. Display: Normalbild, Kopf `[ SAFE_START ]`, alle Werte, IP-Zeile `AP 192.168.4.1  STA off`
   (oder Router), 7 Tasten. Startsignal (kurz–lang) ertönt einmal. Blaue LED blinkt mit 0,5 Hz.
3. WLAN `ADD-Demo` (Passwort `adddemo1`) verbinden, im Browser `http://192.168.4.1/proc` und
   `http://192.168.4.1/log` öffnen: JSON bzw. Log-Zeilen. (`/` liefert noch 404 – Webseiten in W1.)
4. Taste **INIT**: Referenzfahrt zum hinteren Endschalter, danach `[ READY ]`, Klick-Signal beim
   Drücken. Kopf zeigt `LOCAL`.
5. Taste **SERV**: Fahrt zur Wartungsposition (40 mm); **PARK**: Fahrt auf 2 mm; **STOP** während
   einer Fahrt hält sofort an.
6. **Not-Aus** drücken (auch während einer Fahrt): Fehlerbild `FAULT: ESTOP`, ACK-Fläche grau
   „CAUSE ACTIVE …“. Not-Aus lösen: Fläche gelb, 1 s halten → `[ SAFE_START ]`.
7. Kurz tippen auf die ACK-Fläche (< 1 s) quittiert **nicht**.
8. 5 Minuten laufen lassen: kein Neustart, Display aktualisiert sich ohne Flackern.

Bitte die Ausgabe des seriellen Monitors (Start bis `boot: ready`) und die Prüfliste an Claude.
